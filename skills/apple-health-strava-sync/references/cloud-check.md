# 云端重合检查

通过宿主提供且允许的浏览器能力读取已登录账号自己的活动，具体工具按 harness.md 适配。Python 只比对观测文件，不调用 Strava 网络接口，也不读取 cookies。检查无需会员，不触发文件上传。

SYNC 的参数展开方式见 SKILL.md；本文件的命令均使用同一个项目和解释器。

## 采集

1. 用项目 `queue --manifest …` 取得待处理范围；没有 manifest 时先 prepare。读取配置中的账号 ID，核对导航个人资料和活动作者链接。
2. 优先用“我的活动”完整列表。确认关键词为空、没有私人/运动/标记等排除条件，日期降序，连续翻页至早于待处理最早日期。保留每页表格可见单元格和详情链接；加载中不可当空列表。
3. 动态卡片可提供开始时刻、运动图标和距离。动态末尾“没有更多近期活动”只代表近期范围，不等于全部历史。需要时打开列表中实际观察到的详情链接补充开始时间。
4. 验证时间所属时区，以活动所在地和页面为准，不一律套用电脑时区。跨时区活动分成各自时区的观测文件；无法核实时保留待核对。程序拒绝夏令时切换的歧义时刻。
5. 将真实观测保存为项目 `state/cloud_checks/<新时间戳>-observations.json`。采集运动类型、时间、距离、时长口径、链接和页面证据；无距离训练还检查大致地点，无需采集云端完整路线或心率。

## 观测结构（schema_version=1）

必需：`athlete_id`、带时区的 `observed_at`、IANA `timezone`、`timezone_evidence`、`account_evidence`。

`rows` 为列表行数组，每项：
- `cells`：页面表格列的纯文本数组，按实际已核对的“运动、日期、标题、时间、距离、海拔…”顺序。当前支持中文日期 `2026/10/15周四`，距离带 `km`/`mi`/`m` 单位。
- `links`：该行实际活动详情 URL 数组。
- `text`：该行可见文本证据。表头 cells 可为空。

`cards` 为卡片或详情观测数组，每项：
- `url`：实际完整活动详情链接，格式 `https://www.strava.com/activities/数字`。
- `athlete_urls`：该条活动实际作者链接数组。团体卡片必须先打开个人详情，不能混入其他人的活动。
- `sport`：页面运动图标/详情标题中的类型，不从活动名称猜测。
- `time`：页面原始开始时刻；支持中文“今天于 13:57”“2026年9月9日 于 15:48”“2026年9月9日 星期三 15:48”及英文“September 9, 2026 at 3:48 PM”。相对日期按采集当天当地日期解释，跨午夜须重新采集。
- `text`：包含 `距离\n5.15 km`（或 `Distance\n…`）和实际证据文本。详情页可以把读到的距离规范成这两行，保留原始时间/类型证据。无距离时允许省略距离或保留网页空值/破折号。不要从本地清单补齐缺失云端字段。

rows/cards 均可补充：
- duration_seconds 或 duration_text（30:00、1h 5m、30分钟）；duration_kind 为 elapsed/active/moving/unknown，按实际标签填写。列表默认 unknown，不把“时间”自动当有效时长。
- environment：页面明确显示的 indoor/outdoor，缺失为 unknown。
- place：{"label":"实际显示的地区/场所", "source":"strava", "evidence":"页面原文及链接"}。有真实坐标证据时可附 latitude、longitude、radius_m。程序保留两位小数、半径至少 1 公里，不推算街道地址。

同一 URL 的列表行和卡片会合并，冲突报错。网页结构或语言变化时，先检查当前 DOM 再调整采集；不能假设页面结构恒定。

`coverage`：
- 未完整检查时用 `{"complete": false}`。
- 只有所有运动/私人活动均包含、分页无遗漏，并覆盖范围首尾日时，使用 `{"complete": true, "start": "YYYY-MM-DD", "end": "YYYY-MM-DD", "evidence": "实际筛选、页码、最早/最晚日期证据"}`。不要把部分观察声明为完整覆盖。

## 无距离运动的地点排查

对本地缺失/零距离，或候选云端缺失/零距离的每一项，在 review 前完成：

1. 检查 manifest 的 place。有效 GPX 会生成大致坐标范围；无轨迹时查看 state/activity_places.json 中用户提供的本次场所。不从账号住址、其他运动推测本次地点。
2. 打开所有疑似云端活动详情，核对实际可见地区/场所或地图地区标签，保留原文和链接。不从活动标题、浏览器时区或个人资料推定地点，不把云端地点复制成本地证据。页面没有信息时写明“地点未展示”。
3. 在 observations 的 location_checks 中，以本地 activity_id 为键，用非空文本记录实际排查过程及结果，包括无候选、缺失或冲突。无距离项缺少此证据时 review 拒绝进入确认流程。
4. 缺失本地地点时，在完整清单中集中请用户补充大致区域/场所；用户可在知道地点未知的情况下决定排除或上传。不进行反向地理编码，不编造轨迹。

用户明确给出本次训练地点后保存：

~~~sh
SYNC set-place --manifest /实际/manifest.json --file batch_001/实际.tcx --label '用户提供的大致场所' --evidence '用户对应原文'
~~~

可选真实坐标 --latitude … --longitude … --radius-m …。信息按稳定 activity_id 保存，覆盖输入文件夹后仍保留，仅用于排查，不写入 TCX。地点修改后重新 review，不能沿用旧确认。观测文件也可用 local_places: {"activity_id": {"label":…, "source":"user", "evidence":…}} 提供有出处的本地信息。

## 比对与使用结果

```sh
SYNC cloud-check --manifest /实际/manifest.json --observations /实际/observations.json --output /新的/report.json
```

仅生成内部 JSON 报告，不生成查重 CSV；在对话中按编号完整列出疑似项及所有候选供用户确认。不覆盖既有报告，不改上传清单：
- `strong_overlap`：同类型、同一分钟且距离差 ≤ max(100 米, 本地距离的 5%)，双方唯一对应；属于高置信匹配，不是原始文件一致性证明。无有效距离时须同一分钟、同类型、同口径时长差 ≤ max(120 秒, 5%)，且地点范围相近或名称相同、双方唯一对应才标高置信。
- `needs_review`：时间/距离冲突、缺少时刻或多个候选；打开对应详情核对，必要时保留待处理。
- `not_found_in_covered_range`：本次完整观测范围内没有匹配。
- `not_observed_in_partial_snapshot`：观测不完整，不能据此断言云端没有。

无距离候选先按同类型/近似类型及开始时间 ±120 秒筛选；仅有日期时保留同日候选。地点未知/冲突、时长不同也保留给用户，不能静默排除。全程时长与本地起止差比较，有效时长与 Apple duration 比较；仅同地区不构成重合证明。报告列出双方地点来源、地点比较及 location_audit。

网页“移动时间”与 Apple 有效时长不同，不作相等要求；模拟/电动骑行不会合并成普通骑行；室内外通过 environment 独立检查，冲突降为待核对。报告包含观测时间，续传前重新采集，不使用旧报告声称当前不存在。

仅要求检查时，到报告结束。开始上传时执行 `review --manifest … --observations …` 生成绑定完整 manifest/账号的内部 JSON 审核报告和决定模板，向用户直接输出完整编号列表，按 SKILL.md 的用户确认流程处理。strong_overlap 与 needs_review 都必须交给用户决定，不能自动跳过、登记或上传。用户确认排除的记录才记为 exist，uploaded/exist 均从后续待上传列表跳过。不要因为本次云端缺失而撤销已有状态。

审核观测有效期为 24 小时。覆盖不完整、账号不一致、清单内容变化、确认前待上传状态变化均会阻止授权。报告保存在 `state/upload_reviews/`；数据库 upload_reviews 表保存不可被报告文件编辑替换的审核快照、决定、云端链接、用户确认原文和时间。Python 只验证这些结构，真实网页采集和用户授权必须由技能如实执行。
