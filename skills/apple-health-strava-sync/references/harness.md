# 宿主能力与迁移

本 Skill 是指令、浏览器观测数据约定和本地 Python 工具的组合，不自带浏览器驱动。宿主能加载这些指令，并提供下列能力即可适配；不要把工具名称当作能力本身。

| 能力 | 宿主需完成的操作 |
|---|---|
| 本地文件与 Python | 读取导出目录，运行 Python 3.10+，读写项目 state/exports 和 JSON/CSV |
| 浏览器读取与交互 | 发现或打开用户授权的浏览器会话，读取真实页面文字/DOM或截图，点击、翻页、查看详情和活动链接 |
| 本地文件上传 | 将确认队列中的 TCX 交给上传控件/文件选择器/系统对话框，并观察最终保存结果 |
| 人工确认 | 向用户展示完整报告，暂停并收到真实回复，保存决定及原文后继续 |
| 持久存储 | 跨运行保留配置、清单、地点补充和审核记录；临时容器须使用持久目录 |

浏览器工具、桌面工具或宿主允许的 Playwright/Selenium 等均可作为实现方式，不额外安装驱动或启动独立自动化以绕过宿主限制。先读当前工具说明；复用已授权会话，若没有会话则由用户完成登录。不要提取 cookies、登录令牌或把凭据写入观测文件。只有搜索/网页抓取能力不足以完成上传。

## 开始运行

1. 按 SKILL.md 解析项目位置，读取配置并选择实际解释器。优先项目现有 Conda 环境；各系统的解释器位置不同，以发现结果为准，不假定 bin/python。不可用时再使用宿主配置的 Python。
2. 验证 Python 版本、项目读写能力和所需时区，例如用选定解释器执行 `from zoneinfo import ZoneInfo; ZoneInfo('实际时区')`。Windows 或精简环境缺少时区数据时，在所选环境安装 tzdata，或配置系统 IANA 数据；不要用固定偏移代替夏令时。
3. 通过本地读取脚本/配置和工具文档检查能力，不用向 Strava 选文件的方式测试上传。浏览器/上传能力缺失时仍可预览、导出和说明缺少项，不编造云端覆盖、授权或成功结果。
4. 用户指定浏览器优先。否则发现可控且已登录的会话；旧配置 browser 仅是偏好，auto/空值不限定品牌。核对 athlete ID，不能为了适配会话而修改预期账号。
5. 将浏览器观测转换为 cloud-check.md 的 JSON；保留真实原文和来源，不用本地数据补造云端字段。页面语言/结构不受解析器支持时，依据实际证据调整采集或解析器并验证；不凭空解释字段。

可选 local.json 仅用于本机定位项目，结构为 `{"project":"项目绝对路径"}`；不含凭据。它不是必需文件，不随分享包分发。当前目录、环境变量或用户明确参数均可替代它。

## 新项目

用已选择的 Python 执行 Skill 内 scripts/setup_project.py，参数如下（使用真实路径和用户提供的值）：

```text
setup_project.py --project 项目路径 --athlete-id 实际账号ID --start YYYY-MM-DD --sport all --location all
```

脚本创建项目及 sync_config.json，默认 input_directory 为 apple_health_export、browser 为 auto；可指定 --end 和 --input-directory。已有配置或上传清单时拒绝初始化，避免覆盖账号和历史。将解压的健康导出复制到输入目录即可。现有项目直接使用，不初始化、不重置清单。

实际操作入口的参数数组为 `[Python, Skill目录/scripts/sync_strava.py, "--project", 项目路径, 子命令, ...]`。例如依次 prepare --preview、prepare、queue；之后完整采集云端并 review，展示所有疑似项和类型/地点信息。

## 确认与上传的边界

没有特定提问工具要求：宿主可通过聊天、交互表单或人工审批界面显示报告并等待。用户未回复时保存 review_id 和报告位置，结束当前运行等待；不靠超时、默认选项或代理自答作为确认。恢复后核对审核有效期、清单及状态；超时 24 小时或内容变化时重新检查并确认。

必须在用户确认完整清单后才执行 confirm-review 和 upload-queue，再开始向上传控件提供文件。文件选择即可能传输；真正保存成功且类型核对一致后才 record。截图等证据按宿主要求保留，最终活动 URL 必须来自实际页面。

若 Python 与浏览器在不同文件系统，只使用宿主文档支持的文件传递能力，把批准队列中的 TCX 传到浏览器侧；保存原 file、目标路径和活动链接之间的对应关系。不发送健康 XML、数据库或无关文件；传输失败不能登记成功。宿主不支持该桥接时暂停上传并说明缺少能力。

## 迁移与分享

- 分享整个 Skill 文件夹，至少包含 SKILL.md、references/、scripts/。agents/openai.yaml 是可忽略的界面元数据，不是运行依赖。宿主不支持自动发现 Skill 时，可显式加载 SKILL.md 及其引用文件。
- 新用户创建自己的项目；不分发原用户配置、local.json、健康 XML/GPX、state/、exports/、账号或会话凭据。
- 同一用户迁移机器时，另行保留自己的配置、输入、state/ 和所需 exports/。uploaded/exist 标识与文件路径无关；已有审核绑定绝对 manifest 路径，更换目录后重新 prepare、云端检查和用户确认。
- 本地数据库、报告格式和命令在不同宿主间共用；浏览器会话和待决用户授权不可凭迁移自动获得。不同账号使用独立项目，不混用清单。
- 项目版与 Skill 内置版程序保持同一版本更新，避免两份副本功能漂移。已验证本地功能不等于已验证所有宿主的真实浏览器上传。
